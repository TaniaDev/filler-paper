# Plan development

Read [references/current-stage.md](references/current-stage.md) before planning development work.

Treat [references/current-stage.md](references/current-stage.md) as a maintained project snapshot, not as the only source of truth.

Inspect the repository whenever possible because documentation may be outdated.

## Planning process

1. Identify what is already implemented.
2. Identify what is currently in progress.
3. Identify missing foundations or dependencies.
4. Distinguish product work from learning work.
5. Recommend the smallest valuable next step.
6. Divide larger work into ordered and testable tasks.
7. Explain the learning objective of each task.
8. Provide a clear definition of done.

Prefer between one and three immediate tasks.

Do not produce a large roadmap when the user only needs the next step.

Do not skip foundational concepts only to reach a visible feature faster.

Do not introduce advanced architecture before the current requirements justify it.

## Response structure

Use this structure when appropriate:

### Current stage

Briefly describe what the repository currently contains.

### Next step

Recommend the smallest valuable next step.

### Why now

Explain why it is appropriate at the current stage.

### Tasks

Present one to three ordered tasks.

### Learning objective

Explain which engineering or technology concepts will be practiced.

### Definition of done

Describe observable criteria that confirm completion.

### Later

Mention only the most likely following step.

## Task quality

A good task should be:

- small enough to complete and understand;
- valuable to the product;
- testable;
- dependent on already completed foundations;
- connected to a clear learning objective.

When a meaningful milestone is completed, recommend updating [references/current-stage.md](references/current-stage.md).
